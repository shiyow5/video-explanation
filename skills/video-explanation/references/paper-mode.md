# 論文の解説（mode: paper）

台本の先頭に`"mode": "paper"`と`paper`（題名・著者・URL）を書くと、論文の解説として扱う。時間の順に並べる必要がないので、時点（`asof`）の点検はしない。上部の進み具合は全段階の名前を見せる。見本は`template/scripts/paper_sample.json`（架空の論文）。

## 手順

1. 論文を読む。arXivの論文なら、read-arxiv-paperかhuggingface-papersのスキルで本文を読む（要旨だけで書かない）。公開されていない論文や、社外に出せない資料を外部のサービスに送らない。
2. 根拠の一覧を作る。主張ごとに、論文のどの節・式・表・図かを書き出す。数値は表のとおりに写し、データセット・指標・条件を一緒に控える。
3. 構成を決める。既定は落合式の6つの問いで、段階（`stages`）は「どんなもの」「どこがすごい」「手法のキモ」「どう検証」「議論」「次に読む」にする。依頼者のプロジェクトへの示唆を入れるときは、議論のあとに「解説者の見方」の場面として置く。
4. 用語と固有名詞を集める。手順は`terms-and-names.md`。
5. 図を決める。論文の図を使うなら、ライセンスを確かめる（下の表）。使えないときは、diagram・bars・compareなどで描き直し、`source`に元の図の番号を書く。
6. 台本を書き、`check_script.py`で点検する。数式の場面は、各項を`say`で読み下す（記号を読ませない）。
7. 動きを確かめ、書き出し、ファクトチェックをする（論文の本文と表に照らす）。

## 論文の解説で守ること

- 主張ごとに出典を付ける。`source`には論文の節・式・表・図の番号まで書く（例「論文4.2節 表3」）。数字のある場面に出典が無いと、点検でエラーになる。
- 著者の主張と、解説する側の解釈を分ける。解釈の場面には`"interpretation": true`を付ける。見出しに「解説者の見方」の札が出る。読み上げでも「ここからは論文の主張ではなく」と言う。
- 数値は表のとおりに書く。四捨五入や「約」を足すときは、元の値も控えておく。どのデータセットと指標の値かを、画面か読み上げで必ず言う。
- 「最高精度」「初めて」などの言い切りは、論文がそう書いていて、比べた範囲も言えるときだけ使う。
- 限界（議論）は、著者が書いたものと、解説する側が気づいたものを分ける。

## 図のライセンス

| ライセンス | 論文の図を使ってよいか |
|---|---|
| CC BY、CC BY-SA、CC0 | 使ってよい。`credit`に著者と図の番号、`license`にライセンス名を書く |
| CC BY-NC、CC BY-NDなど | 条件しだい（非営利、改変禁止）。点検で注意が出る。枠を重ねることが改変に当たらないかも確かめる |
| arXivの既定のライセンス（arXiv.org perpetual non-exclusive license）、出版社の著作権 | 使わない。描き直す |
| 自分で作った図 | `license`に「自作」と書く |

arXivの論文のライセンスは、論文のページの「License」の欄で確かめる。

## 場面の例

| 問い | よく使う場面 |
|---|---|
| どんなもの？ | icons（扱う対象・目的・条件）、bullets |
| 先行研究と比べてどこがすごい？ | compare（これまでの手法と提案手法）、bars |
| 技術や手法のキモは？ | diagram（処理の流れ）、equation（式と各項）、figure |
| どうやって有効だと検証した？ | table（結果の表。最良の行を強調）、figure（グラフに枠） |
| 議論は？ | bullets（著者が挙げた限界）、bullets＋interpretation（解説者の見方） |
| 次に読むべき論文は？ | bullets、docs（発表順に並べる） |
